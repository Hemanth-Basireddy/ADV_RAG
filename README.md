# ADV_RAG — Conversational RAG Chatbot

ADV_RAG is a PDF-grounded conversational chatbot with a React interface and a FastAPI backend. It uses the project's existing LangChain retrieval pipeline to answer questions about a sample company policy handbook, while retaining in-memory conversation context for follow-up questions.

The backend RAG implementation is preserved from the original learning project. This repository adds a web interface and an API layer that connects it to the browser.

## What it does

Ask questions about the included `data/company_policy.pdf` handbook. The RAG pipeline classifies each message as a document question, a conversation-history question, or general conversation. Document questions are rewritten when needed, matched against the FAISS index, and answered using the retrieved text.

The included handbook is fictional and provided for demonstration only. Answers are generated by an LLM and should not be treated as real company policy.

## Features

- PDF ingestion and FAISS index creation with `ingest.py`.
- Top-3 retrieval from the existing FAISS vector store.
- Intent routing for document questions, conversation-history questions, and general conversation.
- Context-aware follow-up questions using the current session's conversation history.
- Dark, responsive React chat interface with suggested questions, loading feedback, auto-scroll, and keyboard submission.
- Browser-local chat list and separate conversations.
- FastAPI chat and health endpoints with request validation, CORS for local development, and surfaced API errors.
- Existing command-line chatbot remains available through `main.py`.

The frontend does not upload documents, stream generated tokens, or provide per-answer source citations.

## Architecture and request flow

```text
data/company_policy.pdf
        │
        ├── ingest.py: load PDF and split text
        ├── Hugging Face sentence embeddings
        └── FAISS index saved to vectorstore/

React + Vite (localhost:5174)
        │  /api/chat (Vite development proxy)
        ▼
FastAPI (localhost:8000)
        │  rag_chain.invoke(input, chat_history)
        ▼
Intent routing ── DOCUMENT ── contextualize ── retrieve top 3 ── answer from context
              ├── HISTORY ───────────────────── answer from chat history
              └── GENERAL ────────────────────── conversational response
```

### Document preparation

`ingest.py` loads the PDF with LangChain's `PyPDFLoader`, splits it with `RecursiveCharacterTextSplitter` using 500-character chunks and 100-character overlap, embeds the chunks, and saves the FAISS index under `vectorstore/`. The repository includes both the PDF and its existing index; re-run ingestion only when replacing or changing the PDF.

### Retrieval and generation

`src/config.py` loads the `sentence-transformers/all-MiniLM-L6-v2` embeddings, opens the local FAISS store, and configures a retriever to return three chunks. The `ChatGroq` model configured by the existing backend is `openai/gpt-oss-20b` with temperature `0`.

`src/rag_pipeline.py` routes questions using the chains and prompts in `src/chains.py` and `src/prompts.py`. Document questions are contextualized, retrieved, and answered using the returned document text. History questions use prior messages; general questions use the general conversation chain.

### Frontend and API

The React frontend sends `POST /api/chat` requests through Vite's `/api` proxy. Each request contains a `session_id` and `message`; the API invokes the existing `rag_chain` and returns the answer. API session histories are stored in memory and are lost when the backend process restarts. The frontend stores its chat list in browser local storage.

| Endpoint | Purpose |
|---|---|
| `GET /api/health` | API health check |
| `POST /api/chat` | Send a message and receive an answer |
| `GET /docs` | FastAPI interactive API documentation |

Example request:

```json
{
  "session_id": "a-browser-generated-session-id",
  "message": "According to the company policy handbook, how many casual leave days are provided?"
}
```

Example response:

```json
{
  "session_id": "a-browser-generated-session-id",
  "answer": "..."
}
```

## Prerequisites

- Python 3.10 or later (the current environment uses Python 3.12.10).
- Node.js 20.19+ or 22.12+ (the current environment uses Node.js 24.18.0).
- npm.
- A Groq API key.
- Internet access when the Hugging Face embedding model needs to be downloaded, and when making LLM requests.

## Install from GitHub

Clone the repository and enter its directory:

```bash
git clone https://github.com/Hemanth-Basireddy/ADV_RAG.git
cd ADV_RAG
```

Create and activate a Python environment, then install the backend dependencies:

```bash
python -m venv .venv
```

PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

macOS / Linux:

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Create the backend environment file from the template and add your own key:

```powershell
Copy-Item .env.example .env
```

On macOS / Linux, use `cp .env.example .env`. Set `GROQ_API_KEY` in `.env`. Never put a real key in source code or frontend environment variables.

Install the frontend dependencies from the lockfile:

```bash
cd frontend
npm ci
```

The frontend `.env` file is optional for local development; `VITE_API_URL` defaults to `/api`, which Vite proxies to the backend. To create it:

```powershell
Copy-Item .env.example .env
```

On macOS / Linux, use `cp .env.example .env`.

## Run locally

Start the backend from the repository root in one terminal:

```bash
python -m uvicorn api:app --host 127.0.0.1 --port 8000 --reload
```

Start the frontend from `frontend/` in a second terminal:

```bash
npm run dev
```

Vite is configured with `strictPort: true`; if port 5174 is occupied, the frontend exits instead of silently choosing another port.

| Service | Local URL |
|---|---|
| Chat frontend | [http://localhost:5174](http://localhost:5174) |
| API health | [http://localhost:8000/api/health](http://localhost:8000/api/health) |
| API documentation | [http://localhost:8000/docs](http://localhost:8000/docs) |

The original CLI can also be started from the repository root, with the Python environment activated:

```bash
python main.py
```

## Rebuild the vector store

The included FAISS files are needed for API startup and are part of the project. If you replace the PDF, run the ingestion script from the repository root:

```bash
python ingest.py
```

This downloads/loads the configured embedding model if needed and overwrites the local `vectorstore/` index. The runtime loads the FAISS pickle with LangChain's dangerous-deserialization option enabled, so only use a vector store you trust (for example, one generated from this project's ingestion script).

## Limitations and future improvements

- The included handbook is a fictional sample; only the bundled PDF and its FAISS index are used.
- Intent classification can misroute ambiguous questions. Explicitly mentioning the handbook can help the existing classifier select document retrieval.
- Conversation history is held in backend process memory; it is not shared across backend restarts or persisted on the server.
- Chat history is local to the browser. There is no account system, multi-user authentication, or server-side chat-history API.
- Answers are not streamed, and the API does not return retrieved passages or source citations.
- The local CORS allowlist and Vite proxy are configured for development. Production deployment, API authentication, and production CORS settings are not configured.

Possible future work includes source citations, persistent conversation storage, PDF upload and re-indexing from the UI, automated tests, and production deployment configuration.
